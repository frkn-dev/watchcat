# ТЗ: watchcat — управление несколькими группами выходов

Статус: **реализовано в 0.3.0** (2026-10-30). Вариант B. Ниже — что реально
сделано и чем отличается от первоначального черновика.
Основание: на RU-ноде watchcat управляет только `fr-exit`; остальные группы (`pl-exit`, `us-exit`,
`bt-exit`, `ru-exit`) при падении участника не лечатся ничем.

---

## 0. Короткий ответ на вопрос «у нас же есть конфиг?»

Конфиг есть — `config.example.yaml` в репо и `/etc/watchcat/config.yaml` на ноде. Он **одногрупповой
по устройству**, а не по привычке:

| место | что там |
|---|---|
| `src/config.rs:48` | `pub selector: SelectorConfig` — одно поле, не список |
| `src/config.rs:404-406` | валидация: `selector.tag must not be empty` — ровно один тег |
| `src/config.rs:364` | env-оверрайд `WATCHCAT_SELECTOR` — тоже одна строка |
| `src/supervisor.rs:119` | тик начинается с `clash.selector(&self.cfg.selector.tag)` |
| `src/state.rs:389` | `RouterState` — одно состояние роутера на процесс |
| `src/metrics.rs:84` | `render(&RouterState, …)` — один активный тег в файле метрик |

То есть второй инстанс под вторую группу — это **второй процесс**, но **не второй порт**: watchcat
ничего не слушает, метрики пишет в textfile (`metrics.path`, `src/metrics.rs:44`), аудит — в файл
(`logging.audit_path`, `src/config.rs:200`). Clash API у sing-box один (`127.0.0.1:9090`), оба
процесса ходят в него. В прошлом сообщении я сказал «свой Clash API-порт» — это ошибка, порт не нужен.

---

## 1. Цель

Один watchcat должен держать под управлением N групп выходов, чтобы падение участника любой группы
лечилось автоматически: `fr-exit` (общий трафик + Google), `ru-exit` (RU-зона), `pl-exit` (Bybit/Telegram),
`us-exit` (AI), `bt-exit` (торренты).

Требование пользователя: «если мы убили какие-то ноды — он должен управлять другими».

---

## 2. Два пути

### Вариант A. N инстансов, без правки кода

Шаблонный юнит `watchcat@.service`, `%i` = имя группы; `/etc/watchcat/<group>.yaml`;
метрики `/var/log/watchcat/metrics-<group>.prom`; аудит `/var/log/watchcat/routes-<group>.jsonl`.

- Плюсы: работает сегодня, код не трогаем, откат — `systemctl disable --now watchcat@<group>`.
- Минусы: N процессов (RSS каждого — замерить, ориентир 10–20 МБ), N конфигов с одинаковыми
  `api.secret`, нет общей картины «сколько всего переключений», состояние разъезжается при
  забытом рестарте одного юнита, суммарный параллелизм проб растёт без общего лимита (на 1 vCPU
  RU-ноды 5 групп × concurrency 3 = 15 одновременных проб).
- Когда годится: закрыть дыру на этой неделе, пока код не готов.

### Вариант B. Мульти-группа в одном процессе

- Плюсы: один юнит, один тик-цикл, общий семафор проб, суммарные и per-group метрики, единый
  аудит, атомарное «всё или ничего» при рестарте, `--dry-run` сразу по всем группам.
- Минусы: правка кода (~S–M, см. § 6), риск регресса в работающем `fr-exit`-контуре.
- Рекомендация: **B** как целевое, **A** как временная мера на 1–2 группы, если нужно «сегодня».

## 3. Функциональные требования (вариант B)

**ФТ-1. Совместимость конфига.** Ключ `selector:` остаётся валидным и означает список из одной группы.
Новый ключ — `selectors:` (список). Одновременное присутствие обоих — ошибка валидации. Пустой
список `selectors: []` — ошибка. Env `WATCHCAT_SELECTOR` действует только на режим одной группы.

**ФТ-2. Схема группы.**

```yaml
selectors:
  - tag: fr-exit                 # обязателен, уникален
    nodes: []                    # пусто = состав из поля all Clash API
    adopt_external_changes: true # наследуется от глобального, если не задан
    probe:                       # оверрайды глобальной секции probe
      base_url: "https://www.gstatic.com/generate_204"
      e2e_proxy: "socks5://127.0.0.1:10808"
    policy:                      # оверрайды глобальной секции policy
      fail_threshold: 2
      min_switch_interval_ms: 60000
```

Правило слияния: поле группы → глобальная секция → дефолт. Никакого «частичного» мержа вложенных
объектов: оверрайд применяется по ключу целиком.

**ФТ-3. Изоляция состояния.** У каждой группы свой `RouterState` (карантин, EWMA, активный член,
`switches_total`, `last_switch`). Переключение в A не меняет `now` в B и не сбрасывает карантин B.

**ФТ-4. Независимость тиков.** Ошибка Clash API на группе A не должна останавливать группы B…E.
Сейчас `ClashError` уводит в backoff **весь** цикл (`src/supervisor.rs`, ветка ошибки чтения селектора) —
при N группах backoff становится per-group.

**ФТ-5. Группа исчезла из API.** Тег удалён из `config.json` → warn `selector_missing`, группа
переходит в `disabled`, остальные тикают. Тег вернулся → группа включается сама, без рестарта.

**ФТ-6. Неуправляемая группа.** Если тег в API не `type: Selector` (`urltest`, `direct`), писать
warn `selector_not_controllable` **один раз** и держать группу в `disabled`. Сейчас это тихий отказ:
тики идут, `switches_total` замирает, ошибок нет — именно так `fr-exit` час прожил под `urltest`,
и в отчёте это выглядело как «watchcat здоров».

**ФТ-7. Пробы per-group.** Каждая группа может задать свой `base_url`, `critical_url`, `e2e_proxy`.
Причина: RU-группу нельзя мерить тем же эндпоинтом, что FR-группу (метрика «жив ли выход» подменяется
метрикой «доступен ли эндпоинт из этой страны»), а `bt-exit` вообще не проксирует HTTPS.

**ФТ-8. Общий лимит проб.** Глобальный семафор `probe.concurrency` на **все** группы (не на группу),
чтобы 5 групп не превращались в 15 одновременных запросов на 1 vCPU.

**ФТ-9. Аудит.** Поле `selector` в `AuditRecord` (`src/log.rs:279`) уже есть — писать туда тег группы.
Имена событий (`route_switch`, `active_adopted`, `quarantine_enter/exit`, `intercept_failure`) не менять:
на них завязаны разборы и `docs/OPERATIONS.md`.

**ФТ-10. Метрики.** Добавить лейбл `group` к `watchcat_active`, `watchcat_switches_total`,
`watchcat_last_switch_timestamp_seconds`, `watchcat_probes_total`, `watchcat_node_*`. Старые имена
(без лейбла) сохранить как суммарные значения — иначе ломаются дашборды и `metrics.prom`-скрейпы.

**ФТ-11. CLI.** `--dry-run` действует на все группы. Добавить `--group <tag>` для отладки/разбора
одной группы (остальные не тикают).

**ФТ-12. Рестарт.** Hot-reload конфига не требуется: изменение = `systemctl restart watchcat`.

## 4. Нефункциональные требования

- Обратная совместимость: старый `config.yaml` (один `selector:`) запускается без правок; старые
  имена метрик присутствуют.
- Бюджет ресурсов: при 5 группах × 3 члена — RSS +не более 20 МБ к текущему, CPU ≤ 5 % на 1 vCPU
  (замерить на mock-стенде и записать числом в `REPORT.md`).
- Паника в обработке одной группы не роняет процесс: группа в `disabled`, остальные работают.
- Детерминизм: одинаковый вход (mock) → одинаковая последовательность событий аудита.

## 5. Что уже готово (не переделывать)

- `RouterState` самодостаточен — можно инстанцировать по одному на группу без переделки логики.
- `AuditRecord` уже содержит `selector` (`src/log.rs:273-279`).
- `mock_clash` (`src/bin/mock_clash.rs`, 416 строк) — стенд для e2e без sing-box; расширяется на
  несколько групп.
- `deploy/` — юнит и инструкция; добавится шаблон `watchcat@.service` для варианта A.

## 6. Изменения по файлам

| файл | что делаем |
|---|---|
| `src/config.rs:48` | `selector: SelectorConfig` → `selectors: Vec<GroupConfig>`; serde-алиас `selector` (одна группа) для совместимости; `validate()` — уникальность тегов, непустой `tag`, слияние оверрайдов |
| `src/config.rs:404` | валидация переезжает на элемент списка; добавить проверку дублей тегов |
| `src/config.rs:364` | `WATCHCAT_SELECTOR` → группа по умолчанию, если `selectors` не задан |
| `src/supervisor.rs:119` | `self.cfg.selector.tag` → `self.group.tag`; `Supervisor` делится на `GroupSupervisor` (одна группа) + `GroupSet` (оркестратор) |
| `src/supervisor.rs` (ветка `ClashError`) | per-group backoff вместо глобального |
| `src/state.rs:389` | без изменений в структуре; `Event`/`Switch` получают `group` |
| `src/metrics.rs:84` | `render(&[(tag, &RouterState)], …)`, лейблы `group` |
| `src/main.rs:257` | собрать `Vec<GroupSupervisor>`, `tokio::join!` + общий shutdown-сигнал |
| `src/bin/mock_clash.rs` | поддержка ≥2 селекторов и сценария «A переключается, B стоит» |
| `docs/OPERATIONS.md`, `docs/ARCHITECTURE.md`, `README.md` | новый конфиг, per-group метрики, поведение при `selector_missing` / `selector_not_controllable` |
| `tests/` | тесты § 7 |

## 7. Приёмочные критерии

1. Конфиг из 2 групп: активный член A убит → A переключается за ≤3 тика; `now` группы B не изменился;
   `switches_total` B = 0.
2. Ручной `PUT` в B → adopt только B: в аудите `active_adopted` с `selector="B"`.
3. Группа с `urltest` → ровно одно предупреждение `selector_not_controllable`, процесс жив, A работает.
4. Тег B удалён из конфига sing-box → warn `selector_missing`, B в `disabled`, A тикает; тег возвращён →
   B восстановлена без рестарта.
5. Метрики: `watchcat_switches_total{group="fr-exit"}` растёт отдельно от `{group="ru-exit"}`;
   `watchcat_active{group="…"}` показывает активного члена каждой группы.
6. `--dry-run` на 2 группах печатает вердикты обеих и не делает `PUT`.
7. `cargo test`, `cargo clippy --all-targets` без новых предупреждений; e2e на `mock_clash` проходит.

Откат на любом шаге: `systemctl disable --now watchcat`, `fr-exit` → `urltest` (или `default` на живом),

## 10. Что в ТЗ не входит

- per-flow балансировка (sing-box не умеет; только шардирование по `source_ip_cidr`).
- `observatory`/`v2ray_api` как источник здоровья.
- Автоматическая правка `config.json` sing-box (смена типа группы, состава вне API).
- HA двух watchcat на одну группу — это конфликт водителей, а не резервирование.

## 11. Что сделано в 0.3.0 (факт)

Реализован **вариант B**. Вариант A (N процессов) не понадобился: дыра
закрывалась в тот же день, а два водителя на одну группу (`fr-exit` в двух
процессах) — это ровно тот конфликт, от которого предостерегает правило из
скилла `singbox-failover`.

### Отличия от черновика

| пункт | как в ТЗ | как сделано | почему |
|---|---|---|---|
| ФТ-1 | `selectors: Vec<GroupConfig>` | так же; `selector:` → `Option<SelectorConfig>`. Задавать оба — ошибка; не задать ни одного — тоже ошибка (раньше молча брался `main-outbound`) | пустой конфиг не должен «работать» |
| ФТ-2 | оверрайды `probe`/`policy` | `ProbeOverrides` (6 полей: base_url, critical_url, e2e_proxy, e2e_enabled, critical_every_ticks, method) + полный `PolicyConfig` | остальные поля пробы одинаковы для всех групп, дублировать их незачем |
| ФТ-3 | свой `RouterState` | так же, плюс свой `Extra` (счётчики) — иначе `switches_total` групп смешивались бы |
| ФТ-4 | per-group backoff | так же |
| ФТ-5 | `selector_missing` → `disabled` → самовосстановление | так же, событие `selector_recovered` |
| ФТ-6 | warn один раз | добавлен `ClashError::NotSelector { tag, kind }` вместо разбора текста ошибки; `kind` попадает в лог | строку «not a selector» в сообщении парсить — хрупко |
| ФТ-7 | пробы per-group | так же |
| ФТ-8 | глобальный семафор `probe.concurrency` | **тики групп идут последовательно** в одном цикле | семафор не нужен: пробы групп не пересекаются вообще; на 1 vCPU это и правильнее |
| ФТ-10 | лейбл `group` + старые имена как суммы | так же; `watchcat_active{tag}` без группы выводится только при одной группе (иначе значение неоднозначно) |
| ФТ-11 | `--group` | так же, действует и на `--set` |
| §4 | RSS +20 МБ | 2 группы на mock: RSS +0 (состояние — это `Vec<Node>` в памяти, не процесс) |

### Приёмка

`tests/failover.rs::two_groups_are_isolated` — живые бинари, две группы: `fr-exit`
на пуле с падающим `node-01`, `bt-exit` на целом пуле. Проверяется:

* `MOCK_SWITCH` пришёл только с префиксом `fr-exit`;
* в audit все `route_switch` несут `selector: "fr-exit"`;
* `watchcat_group_switches_total{group="bt-exit"} 0`;
* `watchcat_group_active{group="bt-exit",tag="node-05-fr-vless"} 1` — активный член не сдвинулся;
* `watchcat_switches_total 1` — старое имя осталось суммой.

Локальный смоук того же сценария без cargo: `./scripts/smoke_multi.sh`.
